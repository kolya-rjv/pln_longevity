## Architecture in one paragraph

PeTTa is a MeTTa-to-Prolog translator, not an interpreter. A `(= head body)` form is translated into a Prolog
clause and asserted (`PeTTa/src/filereader.pl:167-171`); a `!(...)` form is wrapped in `collapse`, translated to
goals and called (`PeTTa/src/filereader.pl:160-165`); any other top-level form is `add-atom`ed into the space
(`PeTTa/src/filereader.pl:152-156`). A space is a set of dynamic Prolog predicates named after the space symbol,
one per atom arity: `Term =.. [Space, Rel | Args], assertz(Term)` (`PeTTa/src/spaces.pl:2-10`). Functions are
global Prolog predicates, independent of the space they were loaded into (`PeTTa/src/filereader.pl:102-104`:
"Its functions remain the already-compiled clauses from the first load"). Dispatch is decided at compile time
("smart dispatch"): a head already registered as a function becomes a direct predicate call, otherwise the
expression is data (`PeTTa/src/translator.pl:987-1027`; `wiki/Smart-dispatch.md:43`). `eval` re-runs the
translator at runtime (`PeTTa/src/metta.pl:307-312`).

## Python interface

- Module: `PeTTa/python/petta/__init__.py` (the task mentioned `python/petta.py`; in this commit it is a package `python/petta/`). `class PeTTa(verbose=False, petta_path=None)`.
- Engine: in-process `janus_swi` (`janus = importlib.import_module("janus_swi")`, `janus.consult(main_file)`, `janus.consult(helper_file)`), consulted once per process (`CONSULTED` + `CONSULT_LOCK`); `set_prolog_flag(stack_limit, 8000000000)`; runtime located via `PETTA_PATH` env, the bundled `_runtime`, or the checkout root (`_resolve_petta_path`, lines 11-26). If `mork_ffi/.../libmork_ffi.so` exists it chdirs and sets `argv ['mork']` (lines 38-45).
- Methods: `load_metta_file(file_path) -> list[str]` ("Compile a MeTTa file to Prolog and return the results of the run"), `process_metta_string(metta_code) -> list[str]`, `load_metta_file_cached(file_path)` (snapshot replay; "Output printed while loading is not replayed"). Each runs `janus.query_once("run_metta_helper(Verbose, HelperName, Argument, Results)", {...})` and returns `result.get("Results", [])` (lines 62-87).
- Result format: one flat Python list of strings, each the `swrite` serialization of one result, across all `!` forms of the call, in order (`PeTTa/python/helper.pl:6-10` `maplist(swrite,Results,ResultsR)`; `test_petta.py:33` `results[1] == '(2 3 4)'`; `test_load_cache.py:46` `['true', 'true', '2']`). Variables print as `$_0`, `$_1`... (`test_petta.py:54-56`; `PeTTa/src/parser.pl:25-31`). Booleans print as `true`/`false`. The wiki suggests `sexpdata.loads` to parse results (`wiki/Python-interface.md`).
- Errors: a Prolog exception (type error, missing import, Python import failure) propagates as a Python exception (`test_imports.py:70-78` `pytest.raises(Exception, match="python import failed")`; `test_imports.py:93` `match="source_sink"`). Static type errors also print "Type error at <file>:<line> in: <form>" to stderr (`PeTTa/src/filereader.pl:140-145`).
- `verbose=False` asserts `silent(true)` (`PeTTa/python/helper.pl:1-2`) which suppresses the compiled-clause dump.
- `.metta` files: yes via `load_metta_file`; relative imports resolve against the file's directory (`PeTTa/src/filereader.pl:9-16`), not the cwd (`test_imports.py:81-94`).
- Threads/instances: one Prolog engine per process; every `PeTTa()` instance shares it. janus allows calls from any Python thread ("Multiple Python threads can make calls to Prolog"; a non-starting thread gets a temporary engine, "relatively costly" - SWI manual janus-threads), BUT SWI global variables are thread-specific ("Each thread has its own set of global variables, starting with an empty set." - SWI manual section gvar) and PeTTa keeps function metadata, state cells and the specializer's data in `nb_setval` globals (`PeTTa/src/translator.pl:83-84`, `PeTTa/src/metta.pl:302-304`, `PeTTa/src/specializer.pl:28`), so calling from a thread other than the one that loaded the KB would not see that state (inferred). Treat the interface as single-threaded.
- No timeout/cancellation parameter exists on any method.
- Packaging: `pip install .` gives package `petta` + console script `petta` that spawns `swipl --stack_limit=8g -q -s .../src/main.pl -- <args>` (`PeTTa/setup.py:40`, `PeTTa/python/petta/cli.py:17-25`).

## Type checker behaviour

- Default mode: no `--strict`: `strict_mode(false)`, `strict_det(false)` unless `--strict`/`--strict-det` are on `argv` (`PeTTa/src/typecheck/flags_arrows.pl:23-28`). From Python nothing passes these flags, so default mode applies.
- Declarations `(: f (-> A B))` are precached per file before any form runs ("every function type declaration in the file is visible to every definition in it, independent of order", `PeTTa/src/filereader.pl:77-82`); value declarations `(: a A)` are ordinary space atoms and order-sensitive (`PeTTa/README.md:782-783`).
- Declared types are checked at compile time: "provably ill-typed programs are rejected at compile time with the file, line, and offending form" (`PeTTa/README.md:43-55`); the error terms and their messages: "Type mismatch: got ~p but expected ~p", "Type conflict: ...", "Determinism check failed for ~p: ~p", "No matching typed overload for ~p", "Strict mode requires a declared or inferable type for ~p/~p", etc. (`PeTTa/src/main.pl:22-70`). A static error aborts the load: `with_form_location` prints "Type error at ~w:~w in:" and rethrows (`PeTTa/src/filereader.pl:136-149`); `run.sh` then exits non-zero (`PeTTa/test.sh:45-66` relies on this; `fail_*.metta` examples), and from Python it is an exception. A type error inside an imported module aborts the importing program (`PeTTa/examples/fail_import_type_error.metta:1-3`).
- `Atom`, `Expression` and `%Undefined%` are wildcards: `wildcard_type(T) :- atom(T), memberchk(T, ['%Undefined%', 'Atom', 'Expression']).` (`PeTTa/src/typecheck/type_lang.pl:5`) and `runtime_type_ok(_, T) :- wildcard_type(T), !.` (`PeTTa/src/typecheck/value_checks.pl:426`) - no check is ever emitted for them.
- `Atom`-typed ARGUMENT positions receive the source expression unevaluated: `expression_typed(Ty) :- Ty == 'Atom'.` (`type_lang.pl:298`), `translate_args_by_type` keeps such args as data (`PeTTa/src/translator.pl:1408-1413`), "Atom-typed args stay unevaluated data, except underapplied callable expressions representable as a goal-free closure" (`translator.pl:1288-1301`). Example: `(: h (-> Atom Atom)) (= (h $x) (+ $x 42))` -> `(h (+ 1 1))` evaluates to `(+ (+ 1 1) 42)` (`PeTTa/examples/outputtype.metta:7-12`). The README (line 787) says "`Expression`-typed arguments are passed unevaluated (as data)" but the code tests only `'Atom'`; closed issue #185 (July 2026) told users to declare `Expression` for this - whether `Expression` still suppresses evaluation at this commit is unknown (no example pins it).
- A function whose declared OUTPUT type is `Atom` returns its whole body as unevaluated source data: `translate_declared_body(F, out('Atom', _), Expr, [], Expr) :- declared_output_type(F, 'Atom'), !.` (`PeTTa/src/translator.pl:329-330`; `outputtype.metta:4-11`: `(: g (-> Number Atom)) (= (g $x) (+ $x 42))` -> `(g (+ 1 1))` = `(+ 2 42)`). This is a major divergence for hyperon code that declares `(-> Atom Atom Atom)` to prevent argument evaluation: in PeTTa such a function body would not run at all.
- Undeclared functions: "Undeclared functions get local type inference ... Inferred types only ever *add* knowledge ... they are never *demanded* of callers" (`PeTTa/README.md:62-83`); nothing is rejected on inference alone, residual runtime guards (`typecheck_or_error/2`, succeeds on unbound) remain where types are unknown (`README.md:45-48, 400-406`). `--strict` rejects any residual guard and requires declared/inferable types (`fail_strict_missing_type.metta`).
- Declared types are enforced strictly: a declared `Number` parameter rejects `(score none 0.42)` where inference would accept it (`README.md:69-83`); type variables in declarations are promises checked at every call (`README.md:129-160`); unions must be declared (`README.md:269-274`).
- Exhaustiveness/determinism checks apply only to explicit `-[det]->`/`-[semidet]->` arrows; plain `->` "claims nothing and is checked for nothing" (`README.md:612-636`).
- Overloaded declarations (several `(: f ...)`): compile to runtime dispatch with output guards; a call with no surviving overload throws `no_matching_overload` (`PeTTa/src/translator.pl:1109-1140`; `PeTTa/examples/types_nondet.metta`).
- Late declarations (type arriving in a later file than the definition) warn and recompile the function (`README.md:689-695`; `test_imports.py:97-116`).
- Builtin signatures come from `src/typecheck/builtin_registry.pl` (e.g. `'+'/2 ... ['Number','Number'] -> 'Number'`, `'<'/2 -> 'Bool'`), so `(+ "a" 1)` with literal args is a compile-time "Type mismatch" (`README.md:54`).
- Runtime residual guards check through user-extensible `get-type` reflection (`value_checks.pl:421-449`).

## Nondeterminism and match semantics

- Clauses: each `(= ...)` equation is one Prolog clause, asserted in source order; calling a function backtracks through them (Prolog semantics). Explicit `-[det]->`/`-[semidet]->` declarations add a commit cut (`PeTTa/src/translator.pl:135-141, 175-178`).
- Top level: `!expr` is evaluated as `(collapse expr)` -> `findall`, so ALL solutions are produced, in solution order, and printed one per line (`PeTTa/src/filereader.pl:160-165`; `PeTTa/src/main.pl:100-103`). An expression with no solution prints nothing (the `test` form displays an empty solution set as `()`).
- `collapse` is `findall` (ordered list, duplicates kept); `superpose` is disjunction/`member`; `(empty)` is `fail`; `once`, `(cut)`, `hyperpose` (parallel, order not preserved - examples sort with `msort`) are available.
- `match`: the pattern is unified against the space's clauses (`space_call(Term)`), the template is translated like any expression (known function heads in the template are called, `PeTTa/src/translator.pl:880-897`), but values bound FROM the space are not re-evaluated: "Match does not automatically interpret the returned pattern as code" (`PeTTa/examples/eval.metta:5-9`); `!(add-atom &self (= (addnormal) (+ 1 3)))` then `!(test (match &self (= (addnormal) $X) $X) (quote (+ 1 3)))` (`PeTTa/examples/he_atomspace.metta:3-6`). Use `(eval ...)` or `lib_he`'s `add-reduct` where hyperon would have reduced.
- `match` on a variable pattern enumerates all atoms (`PeTTa/src/spaces.pl:226-229`); `(, p1 p2 ...)` conjunctions; cyclic results are rejected (`\+ cyclic_term(OutPattern)`).
- `match` results are nondet (`builtin_registry.pl:127`), so a `-[det]->` body may not contain a `match` (`README.md:596-610`).
- Nondeterministic `let` values multiply results (`PeTTa/examples/tests.metta`, `let_superpose_if_case.metta`).
- Result printing: `swrite` (`PeTTa/src/parser.pl:9-53`): lists as `(a b c)`, improper lists as `(cons a b)`, variables `$_N`, strings quoted with escapes, numbers via `write/1`.
- `get-type` is nondet (`builtin_registry.pl:130`); `index-atom` with unbound index enumerates (`README.md:420-421`).

## Timeouts and interrupts

- Nothing built in. Grep of `src/`, `lib/`, `python/`, `README.md` for `call_with_time_limit`, `time_limit`, `alarm`, `interrupt`, `sigint`, `timeout` finds no mechanism (only `snapshot`, `with_mutex`, `transaction`, `thread_local`, `concurrent_and` hits). The only time bounding upstream is the external `timeout -k 5 240 sh run.sh ...` wrapper in the test matrices (`PeTTa/examples/soundness_matrix.sh:70-97`, `PeTTa/examples/fuzz_matrix.sh:43`).

## Performance claims (upstream prose, not reproduced here)

- Tail-recursive `(fib 100000)` "takes about 170ms on M4 processor" (`wiki/Smart-dispatch.md:28`); `(fib 500000)`: 1.5s smart-dispatch/call vs 2.9s `reduce` vs 3.8s `eval` (`wiki/Smart-dispatch.md:68-90`); naive `(fib 33)`: 1.8s / 4.0s / 18s (`wiki/Smart-dispatch.md:97-101`).
- "Types make code *faster*, not slower: resolved arithmetic fuses to native `is/2` ... about twice as fast as the untyped translation was before." (`PeTTa/README.md:57-60`).
- Caveat: "Interpreters that call `eval` per iteration pay for a (typed) translation each time - that pattern was always slow" (`PeTTa/README.md:789-790`); `reduce`-based dynamic dispatch is 2-4x slower than direct calls (`wiki/Smart-dispatch.md:39`).
- Tabling/memoization available through Prolog (`:- table fib/2.` via `translatePredicate`, `wiki/Prolog-interop.md:3-18`; `lib/lib_memo`, `lib/lib_tabling`).
- Evidence quality: numbers appear only in wiki prose; no benchmark harness with recorded numbers is in the repo.
