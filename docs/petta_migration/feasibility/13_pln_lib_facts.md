## 1. Sentence format, truth values, evidence stamps (task item 3)

- A knowledge item is `(Sentence (<Term> (stv <strength> <confidence>)) (<id1> ... <idn>))`. Evidence: wiki PLN.wiki/Home.md:59 (`(Sentence ($Term (stv $Strength $Confidence) ($EvidenceID))`), lib_pln.metta:362 (`(PriorityRank (Sentence ($x (stv $f $c)) $Ev1)) $c`), every example, e.g. PLN/examples/Smokes.metta:24-26 `(Sentence ((Inheritance (Product Anna Bob) friend) (stv 1.0 0.9)) (3))`.
- Terms are plain MeTTa expressions: `(Inheritance A B)`, `(Implication A B)`, `(Implication (Inheritance $1 Penguin) (Not (Inheritance $1 (IntSet flies))))` (variables allowed inside a term; FlyingRaven.metta:21-25), `(Not X)`, `(Similarity A B)`, `(Equivalence A B)`, `(Member A B)`, `(Evaluation (Predicate p) (List (Concept c)))`, `(Operation X op)`.
- The stamp is a tuple of evidence IDs. Inputs carry one ID each, `(1)`, `(2)`, ...; derived sentences carry the sorted union, e.g. `(1 4 6)` (FlyingRaven.metta:42). Wiki rule: "Running ID, so for Sentence_i assign evidence ID i. Except if one knows 2 inputs are statistically dependent, one can give them the same ID" (Home.md:71). IDs are compared with `is-member`/`==` and sorted with `msort`, so any atoms work, but the examples use integers.
- The KB passed to the API is a plain tuple of sentences, usually a function `(= (kb) ((Sentence ...) (Sentence ...)))` (Smokes.metta:12-47), or built at call time with `append` (Robot.metta:32-33).

## 2. Per-term base rates: STV (task items 3 and 4)

- lib_pln.metta:67-68: `;Forward declaration` / `(= (STV $stv) (empty))`. This IS the only STV equation in the library (grep confirms). It is a catch-all clause whose body is `(empty)`, i.e. "no result".
- User code adds one clause per term: `(= (STV Anna) (stv 0.1667 0.9))` (Smokes.metta:5-10; FlyingRaven.metta:5-10 including `(= (STV (IntSet flies)) (stv 0.16 0.9))`; Toothbrush.metta:5-16; RuleTester.metta:6-14; evaluationImplicationRuleA.metta:7-10 uses compound terms `(STV (List (Concept Tom)))` and `(STV (Predicate IsFat))`). The examples use uniform "1/N" style values (0.1667 for six people, 0.16, 0.125, 0.1, 0.142, 0.25, 0.333, 0.5) with confidence 0.9-1.0.
- Where STV is consumed: Deduction rule lib_pln.metta:236-242 `(Truth_Deduction (STV $A) (STV $B) (STV $C) $T1 $T2)`; Induction 246-251; Abduction 254-259; Inheritance inversion 287-288 `(Truth_inversion (STV $B) $Truth)`; Implication inversion 291-292; Equivalence-to-Implication 295-301; transitive similarity 304-308; Evaluation-implication 311-315; Member deduction 319-323. NOT consumed by Revision (211-213), Modus Ponens (216-218), Symmetric MP (226-229), the three Evaluation/Inheritance replacement rules (263-281), Negation elimination (284).
- VERDICT on the suspicion "`(= (STV $stv) (empty))` is the only STV equation so `(STV $A)` inside the rules evaluates to empty": half right. It is the only equation IN THE LIBRARY, and for a term with no user-declared clause `(STV term)` does evaluate to nothing, which makes every rule listed above that consumes it produce NO conclusion for that term (in PeTTa a failed subgoal fails the clause; the rule body is just a nested call, there is no explicit guard, lines 236-242). But STV is a nondeterministic function with user-extended clauses: with `(= (STV A) (stv 0.5 0.9))` present (DeductionRevision.metta:5-8) the call yields that stv (the catch-all clause contributes nothing and the specific clause contributes one value), and the examples prove the deductive rules fire: FlyingRaven's expected `(Inheritance Sam (IntSet flies))` = `(stv 0.9703557256235827 0.6932852196717858) (1 4 6)` is exactly two chained applications of `Truth_Deduction` with base rate 0.16 (checked by hand: 0.99*0.99 + 0.01*(0.16-0.16*0.99)/0.84 = 0.980119, c = 0.99*0.99*0.9*0.9 = 0.793881; then 0.980119*0.99 + 0.019881*0.0019048 = 0.97036, c = 0.980119*0.99*0.793881*0.9 = 0.69329). So: STV is a function from a term to its base-rate stv, defaulting to "no base rate = no syllogistic inference about that term"; modus ponens, revision and negation still work without it (Toothbrush.metta declares STV only for atomic symbols, never for its `(Inheritance X heated)` terms, and still derives `(Inheritance X removed)` through modus ponens alone, expected stamp (2 3 4 5 6 7 10 11 12 13 14), Toothbrush.metta:75-79).
- Consequence for this KB: every node that must take part in deduction needs an `(= (STV <node>) (stv p c))` clause (with the up/down split below: two per node). The KB has no node probabilities today (pln_deduction.metta:72-75 says so explicitly: "We don't store node strengths yet").

- `(PLN.Derive $Tasks $Beliefs $maxsteps $taskqueuesize $beliefqueuesize)` :399-400.
- `(PLN.Derive $Tasks $Beliefs $maxsteps)` :402-403 -> queue sizes from config.
- `(PLN.Derive $Tasks $Beliefs)` :405-406 -> `(PLN.Config.MaxSteps)`.
- `(PLN.Query $Tasks $Beliefs $term $maxsteps $taskqueuesize $beliefqueuesize)` :416-421.
- `(PLN.Query $kb $term $maxsteps $taskqueuesize $beliefqueuesize)` :423-424 -> Tasks = Beliefs = $kb.
- `(PLN.Query $kb $term $maxsteps)` :426-427; `(PLN.Query $kb $term)` :429-430.
- Defaults: `(PLN.Config.MaxSteps) 100` :326, `(PLN.Config.TaskQueueSize) 10` :329, `(PLN.Config.BeliefQueueSize) 100` :332. Examples override: `(PLN.Query (kb) (Inheritance A D) 100 30 100)` (DeductionRevision.metta:17), `... 5)` (RuleTester.metta:35), `... 1)` (inversion.metta:17).
- Returns: PLN.Derive returns the pair `($Tasks $Beliefs)` — the remaining task tuple and the final belief tuple, every element a full `(Sentence (term (stv s c)) (stamp))` (:379, :418). PLN.Query returns `((stv s c) (id ...))` — the truth value AND the evidential base of the single best-confidence belief whose term is `==` to the query term (:409-421: `(case (== $Term $term) ((True ($TV $Ev))))` then `BestConfidenceCandidate`), or `()` when no belief has that term (BestCandidate's initial candidate is `()` :351-359, :413; Robot.metta:41 tests `(== (PLNcategorizeObject ...) ())`). There is NO derivation path / proof tree in the return value or anywhere in the data structure: a Sentence stores only term, stv and stamp (:362, :380-390). The wiki's Home.md:49 shows `PLN.Derive` with a `$queryTerm` argument; the code has none (:377-406) — wiki is stale there.
- `==` is Prolog structural identity in PeTTa (PeTTa/src/metta.pl:61 `'=='(A,B,R) :- (A==B -> R=true ; R=false).`), so a query term must be fully ground and syntactically identical; variables in the query term will not unify (Robot.metta queries with both arguments bound).
- Ties: `BestCandidate` uses strict `>` (:356), so among equal confidences the earliest in tuple order wins; the result is deterministic for a fixed input ordering.
- Side effect: every Derive step prints `(SELECTED (Sentence ...))` with `println!` (:391).

## 4. Truth formulas as written in lib_pln.metta (task item 3)

Helpers: `(/safe $A $B)` = `(if (> $B 0.0) (/ $A $B) (empty))` :10-13 — division by zero yields NO result (the whole enclosing computation disappears). `Truth_c2w c = c/(1-c)` :71-72 (empty when c=1), `Truth_w2c w = w/(w+1)` :75-76, `Truth_or a b = 1-(1-a)(1-b)` :79-80.

Deduction :84-99:
```
(= (Truth_Deduction (stv $Ps $Pc) (stv $Qs $Qc) (stv $Rs $Rc) (stv $PQs $PQc) (stv $QRs $QRc))
   (if (and (conditional-probability-consistency $Ps $Qs $PQs)
            (conditional-probability-consistency $Qs $Rs $QRs))
       (stv (if (< 0.9999 $Qs) $Rs
                (+ (* $PQs $QRs) (/safe (* (- 1 $PQs) (- $Rs (* $Qs $QRs))) (- 1 $Qs))))
            (* (* $PQs $QRs) (* $PQc $QRc)))
       (stv 1 0)))
```
i.e. s_AC = s_AB*s_BC + (1-s_AB)*(P(C) - P(B)*s_BC)/(1-P(B)); c_AC = s_AB*s_BC*c_AB*c_BC (confidence is weighted by the STRENGTHS; the node confidences Pc/Qc/Rc are ignored). Consistency :42-54: `0 < P(A)`, `clamp((P(A)+P(B)-1)/P(A),0,1) <= s_AB <= clamp(P(B)/P(A),0,1)`, same for (B,C). If either fails the rule returns `(stv 1 0)` — a real sentence with zero confidence, which still enters the queues (it is the lowest-priority item, so LimitSize evicts it first). `Consistency_ImplicationImplicantConjunction` :56-63 is defined but unused. `simpleDeductionStrength` :184-194 is the same strength formula returning `(empty)` on inconsistency, used only by the Evaluation-implication rule.

Revision :136-143:
```
(= (Truth_Revision (stv $f1 $c1) (stv $f2 $c2))
   (let* (($w1 (Truth_c2w $c1)) ($w2 (Truth_c2w $c2)) ($w (+ $w1 $w2))
          ($f (/safe (+ (* $w1 $f1) (* $w2 $f2)) $w)) ($c (Truth_w2c $w)))
         (stv (min 1.0 $f) (min 1.0 (max (max $c $c1) $c2)))))
```
Confidence-weighted mean strength; confidence from summed weights, never below either input. Any input with c = 1.0 makes `Truth_c2w` empty, so the revision produces nothing. Rule :211-213 fires for two sentences with the SAME term `($T $T1) ($T $T2)` and disjoint stamps.

Modus Ponens :124-126: `(stv (+ (* $Ps $PQs) (* 0.02 (- 1 $Ps))) (* (* $Ps $PQs) (* $Pc $PQc)))` — the 0.02 term is a fixed P(Q|not P) assumption. Checked against Smokes.metta:49-52: Edward smokes (1.0,0.9) and smokes->cancerous (0.6,0.9) give (0.6, 0.486) with stamp (2 10). Symmetric MP :129-133 assumes `$snotAB 0.2`.

Induction :102-110: `s = s_BA*s_BC*P(B)/P(A) + (1 - s_BA*P(B)/P(A)) * (P(C) - P(B)*s_BC)/(1-P(B))`, `c = Truth_w2c(s_BC*c_BC*c_BA)`. Abduction :112-121: `s = s_AB*s_CB*P(C)/P(B) + P(C)*(1-s_AB)*(1-s_CB)/(1-P(B))`, `c = Truth_w2c(s_AB*c_AB*c_CB)`. Both go through `Truth_w2c`, so their confidence is at most 0.5 (w<=1 -> c<=0.5).

Negation :147-148: `(stv (- 1.0 $s) $c)`; rule :284 `(|- ((Not $A) $T)) ($A (Truth_Negation $T))` — a TOP-LEVEL `Not` only; "negation introduction now handled by Translator" (:283 comment) — there is no rule that turns `(Implication A (Not B))` into anything chainable.

Inversion :150-153: `(stv $ABs (* $Bc (* $ABc 0.6)))` — strength copied, confidence = c_AB * c_B(base-rate confidence) * 0.6, with the comment "not according to OpenCOG classic". Rules :287-292 apply it to EVERY Inheritance and Implication sentence automatically (single-premise rule, selected via `(|- $x)` :390). Equivalence->Implication :156-162, transitive similarity :165-181, evaluation implication :197-204 are not relevant to this KB.

## 5. Control loop and StampDisjoint (task item 3)

`PLN.Derive` :377-397, per step:
1. Stop when `steps > maxsteps` or Tasks is empty; return `($Tasks $Beliefs)`.
2. Select the task with the highest confidence: `(BestCandidate PriorityRank () $Tasks)`, `PriorityRank` = the sentence's confidence (:362); priority IS confidence, nothing else (no strength, no novelty, no age).
3. Derive: for every belief `(Sentence $y $Ev2)` whose stamp is disjoint from the task's, try the two-premise rules in both orders `(|- $x $y)` and `(|- $y $x)` (:385-388), stamping results with `(msort (append $Ev1 $Ev2))` (:384); plus the single-premise rules `(|- $x)` (:390) with the task's own stamp. `case` keeps only results that are `($T $TV)` pairs; `(empty)` results vanish.
4. New tasks = `LimitSize(exclude-item(selected, ConcatUnique(Tasks, derivations)), taskqueuesize)`; new beliefs = `LimitSize(ConcatUnique(Beliefs, derivations), beliefqueuesize)` (:392-393). `ConcatUnique` (:29-34) deduplicates syntactically identical sentences (same term AND stv AND stamp); `LimitSize` (:370-374) repeatedly drops the LOWEST-confidence item (`PriorityRankNeg` :366) while `length >= size`, so a queue of size N retains at most N-1 items.
5. Recurse with steps+1.

So the task queue is a confidence-ranked priority queue of "sentences not yet expanded", the belief buffer is everything known, both bounded by eviction of the least confident. A selected task is expanded against ALL beliefs in one step, then removed from the task queue (it stays a belief). The whole closure is recomputed on every PLN.Query call; nothing is cached or written back into a space.

`StampDisjoint` :335-342: True iff no ID of stamp 1 occurs in stamp 2 (recursive `is-member`). It gates every two-premise derivation (:383), so no sentence is ever combined with another that already incorporates one of its evidence IDs: a revision of two paths that share a link is impossible (prevents double counting), and a conclusion can never be chained with one of its own premises. Single-premise rules (inversion, negation) are not gated and keep the stamp. Evidence IDs are the only provenance.

## 8. Mapping options (task item 6)

Common to all options: links become `(Sentence ((Implication <from> <to>) (stv s c)) (<id>))`; every node needs an `(= (STV <node>) (stv p 0.9))` clause (base rate p; see §9 for the consistency constraint); the stv of a sentence is interpreted by lib_pln as P(to|from), not as a magnitude. Hazard-ratio records are materialised as one sentence each with `calibrate-tv`'s (s,c) (Python or a hyperon pre-pass can do the lift; PeTTa could also run `match` over the raw atoms, but the repo's lift code is validated on hyperon only). DrugAge rows are materialised one sentence per row with the row id as evidence ID, so Revision (lib_pln.metta:211-213) merges rows of the same compound and sign (disjoint stamps), instead of dropping 169 of 170 resveratrol rows. The constant `(Effect Lifespan Mortality Neg (stv 1.0 1.0))` becomes one sentence; its c = 1.0 is fine inside deduction but any c = 1.0 sentence can never be revised (`Truth_c2w` :71-72 is empty at c = 1), so give it c = 0.99 if it is ever a revision input.

(a) `Implication A B` for Pos and `Implication A (Not B)` for Neg (or a `decreased-B` concept).
- How: Pos -> `(Implication A B)`; Neg -> `(Implication A (Not B))` or `(Implication A B-decreased)`.
- Pros: closest to textbook PLN; one sentence per link; `Not` is a real PLN term with a base rate `(= (STV (Not B)) ...)`.
- Cons (fatal for the `Not` form): the deduction rule unifies the middle term syntactically — `(($LinkType $A $B) $T1) (($LinkType $B $C) $T2)` (:236-237) — so `(Implication A (Not B))` never chains with `(Implication B C)`, and the only negation rule strips a top-level `(Not X)` sentence (:284); nothing rewrites `(Implication B C)` into `(Implication (Not B) ...)`. A Neg hop therefore terminates every chain. The `decreased-B` concept form is really option (c) with half the nodes missing: `B-decreased` needs its own outgoing links (what does lowering B do to C?), which is exactly the up/down split. Hazard-ratio lifts (HR<1 -> Neg) and DrugAge rows (pct<0 -> Neg) have the same problem. Provenance: evidence base only.
- Arithmetic for the procedures: unchanged shapes could be produced by an adapter, but Neg chains would simply disappear from results.

(b) Carry the sign outside PLN; chain magnitudes only.
- How: send every link as an unsigned `(Implication A B)` regardless of sign, keep a side table `id -> sign`. Query `(Implication A C)`; the returned evidence base `(id ...)` lists the premise links; sign = product of the signs of those ids.
- Pros: smallest change: one sentence per link, nodes not doubled, the number of base rates equals the number of nodes; PLN.Query's return is directly usable; today's unique-path graph makes the evidence base exactly the path's link set, so the sign product is exact.
- Cons: the evidence base is a SET, not a path. As soon as Revision merges two paths (the whole point of adopting PLN), the stamp is the union of both paths' links and the sign product over the union is meaningless when the paths disagree in sign (a Pos path and a Neg path to the same conclusion would be averaged into one stv by Revision :136-143 and the sign would be lost); an abductive/inductive side-derivation for the same term (lib_pln.metta:246-259) can also win `BestConfidenceCandidate` with a stamp that is not a path at all. It also mis-states the semantics to PLN: a protective link is given as P(C|A) = magnitude.
- Hazard-ratio / DrugAge lifts: fine mechanically (ids per record/row), but a compound with both life-extending and life-shortening rows would be revised into one unsigned stv.

(c) Split each node into up/down concepts (A-up, A-down); the sign becomes path structure.  <- RECOMMENDED
- How: Pos A->B with (s,c) becomes two sentences `(Implication A-up B-up)` and `(Implication A-down B-down)`, both (s,c), both with the link's evidence id (the wiki explicitly allows a shared id for statistically dependent inputs, Home.md:71; no derivation can use both halves of one link anyway unless the graph has a cycle). Neg A->B becomes `(Implication A-up B-down)` and `(Implication A-down B-up)`. A hazard-ratio record with HR>1 maps to `X-up -> Outcome-up`/`X-down -> Outcome-down` with calibrate-tv's (s,c) and the record name as id; HR<1 to the crossed pair. A DrugAge row with pct>0 maps to `Compound-up -> Lifespan-up` (+ mirror), pct<0 to `Compound-up -> Lifespan-down` (+ mirror), id = row id; the bridge is `Lifespan-up -> Mortality-down` (+ mirror). Base rates: two per node, e.g. `(= (STV CHD-up) (stv p 0.9))`, `(= (STV CHD-down) (stv p 0.9))`.
- Queries: today's `(infer A C)` becomes two PLN.Query calls, `(Implication A-up C-up)` -> `(signed Pos (stv s c))` and `(Implication A-up C-down)` -> `(signed Neg (stv s c))`, each returning at most one result or `()`; an adapter can return the same `(signed ...)` shapes to the procedures. Paths of different signs land on DIFFERENT query terms, so Revision only ever merges same-sign paths — the sign is never lost, and a compound with mixed-sign rows yields both a Pos and a Neg answer, which `rank-score` already handles.
- Pros: no change to lib_pln; signs exact under revision; evidence stamps give provenance per link; the mirror sentences are inert unless a `-down` source is queried.
- Cons: nodes and base rates double (60 nodes for the 30-node graph), sentences double (56 for 28 links), which halves the usable queue budget (see §11); the automatic single-premise Inversion rule (:291-292) produces reverse links for every sentence, and Induction/Abduction (:246-259) produce sibling links, all competing for queue slots; query terms must be ground and exactly spelled (`==`).
- Provenance: see §10.
- Procedure arithmetic: `rank-score`, abduction's max/noisy-OR, `relevance-on`, personalised scores keep working on the adapter's `(signed ...)`; `pos-transmission`/`linage-transmission` get at most one (revised) value instead of the first of several; the hand composition `c = c_l*c_base*0.9` in pln_counterfactual.metta:282-284 and pln_linage2.metta:312-314 should be replaced by querying `(Implication Lever-up M-down)` directly (otherwise two different deduction formulas coexist); `explain` must be re-implemented on top of stamps (§10).

Recommendation: (c), with evidence ids assigned per source record (one id per curated Effect atom, per hazard-ratio record, per DrugAge row), base rates set uniformly at first (p = 0.1 for every up/down node, which keeps the consistency check satisfied for all strengths <= 1), and queue sizes raised above the closure size.

## 9. How the pinned numbers would change (task item 7)

Hand-computed with the formulas of §4 (python arithmetic only, no PLN run), base rate p for every node unless stated:

| Chain | today (s, c) | PLN deduction, p = 0.1 | p = 0.5 |
|---|---|---|---|
| SASP->CHD (1 hop through DNAmPAI1): (0.70,0.65)+(0.6,0.85) | 0.42, 0.49725 | 0.4333, 0.23205 | 0.54, 0.23205 |
| CellularSenescence->CHD (2 hops) | 0.357, 0.29089 | 0.3778, 0.07692 | — |
| D+Q->CHD magnitude (3 hops) | 0.2499, 0.17017 | 0.2852, 0.01517 | — |

- Strength: the product gains a base-rate term `(1-s_AB)*(p - p*s_BC)/(1-p)`, so strengths go UP slightly (and more with larger p); with equal base rates <= 0.5 the consistency checks always pass; with unequal base rates they fail whenever `s_BC > P(C)/P(B)` and the conclusion becomes `(stv 1 0)` (e.g. P(B) = 0.5, P(C) = 0.1, s_BC = 0.6 -> `(stv 1 0)`), so base rates are not free parameters.
- Confidence: `c = s_AB*s_BC*c_AB*c_BC` — multiplied by the strengths instead of by 0.9. For this KB's strengths (0.5-0.85) that is a per-hop factor of ~0.3-0.7 instead of 0.9: confidences fall 2x (1 hop) to 11x (3 hops) and decay much faster with length; the threshold-based tests (0.3 in test_drugage_ranking_contract.py:259) and the API's `confidence_threshold` would need re-tuning. A zero-strength link zeroes the confidence of everything chained through it: the ITP-negative resveratrol row (stv 0.0 0.9), today "confident null" `(signed Neg (stv 0.000 0.810))` (docs/etl_inference_wiring.md:173-182), becomes `(stv 0 0)` at Mortality, i.e. unranked rather than confidently null. The PeTTa-bundled older variant instead uses `min` of all five confidences (no decay at all with length), so the choice of lib_pln copy changes the numbers again.
- Revision when several paths or rows exist: weights add (`w = c/(1-c)`); two paths at c = 0.9 give c = 0.947; 170 resveratrol rows (1 ITP null at 0.9, 100 significant invertebrate rows at 0.315, 69 null rows at 0.126, strengths 0/0.3/0.1) give about (0.228, 0.985) — replication count is rewarded and confidence saturates near 1, strength becomes the confidence-weighted mean; the 170-row merge needs 169 revision steps and all rows resident in the belief buffer (> default 100), see §11.
- Ordering: D+Q > Fisetin > Spermidine and Metformin > Berberine survive (monotone in s and c, same path structure), but every pinned (s, c) in tests/test_pln_deduction.py:104-176, test_patient_grounding.py:226-231, test_drugage_calibration.py:242-252, test_drugage_ranking_contract.py:246-263, test_counterfactual.py:203-214 changes.
- The 0.9 discount has no analogue inside lib_pln (the deduction confidence has no tunable constant; inversion hard-codes 0.6, modus ponens 0.02, symmetric MP 0.2). It can be emulated outside: pre-scale every link confidence by 0.9 before building sentences (then a k-hop chain carries 0.9^k, not 0.9^(k-1)), or post-scale PLN's answer by 0.9^(|stamp|-1) when the stamp is a single path.

## 10. Provenance recovery (task item 6)

`PLN.Query` returns only `((stv s c) (ids))`; there is no derivation record (§3). With one evidence id per link, the stamp of a conclusion is the set of links used. For a DAG with a unique path (today's graph) the path can be rebuilt outside PLN by restricting the link graph to the stamp's ids and walking from A-up to C-up/C-down — this reproduces `explain`'s `(Chain (n0 ... nk) ...)` exactly, with the sign known from the query term. When Revision merged k paths the stamp is their union and the walk yields k paths (all genuine). When the best candidate came from an inductive/abductive/inverted side-route, the stamp is not a path and the walk fails — detectable (no A->C walk exists), and in that case `PLN.Derive`'s full belief tuple can be read instead: every intermediate conclusion `(Implication A-up X-*)` sits there with its own stamp, and the sub-conclusions whose stamps are subsets of the final stamp are the chain prefixes. Shared evidence ids (deliberately dependent inputs, Home.md:71) break the 1:1 id->link reading and must be avoided for links.

## 11. Does the confidence-ranked queue change anything? (task item 8)

30-node / 28-link graph (closure 100 conclusions, no pair with two paths): Revision never fires between deductive paths, so the queue does not change WHICH conclusions are derivable, but it decides which are REACHED under the defaults. With `PLN.Query (kb) term` the 28 (56 after the up/down split) sentences are both the initial tasks and beliefs; `LimitSize` keeps at most 9 tasks and 99 beliefs (lib_pln.metta:371 uses `<`), and the closure plus inputs is 128 sentences (256 split) before counting the automatic by-products: Inversion gives every Implication a reverse twin at c = 0.6*c_AB*c_B(=0.9), i.e. 0.27-0.46 — HIGHER than every 3-4-hop deduction (0.015-0.08 under PLN's formula) — and Induction/Abduction add sibling links at c <= 0.5. Those by-products outrank the long chains in both queues, so the D+Q/Spermidine-class conclusions are evicted or never expanded with the default 10/100/100; the sizes must be raised to at least the full closure plus by-products (hundreds), and MaxSteps to the number of sentences that must be expanded, after which each PLN.Query is a full closure recomputation (every call starts from scratch, :416-421) rather than the 0.02 s per `infer` measured today; the 870 explain queries of the memory note would be 870 closure runs. Cost per step is linear in beliefs for selection and quadratic for `LimitSize`/`ConcatUnique` (:29-34, :351-374), so absolute times on PeTTa are unknown and cannot be measured here (SWI-Prolog is not installed). The queue does give something `infer` lacks: a cycle no longer hangs (stamps + bounded queues + MaxSteps terminate), though its conclusions would still be numerically arbitrary.

DrugAge-scale graph (3,423 rows, 1,027 compounds, plus hallmark/gene links): here the queue IS the control: only the most confident sentences get expanded (ITP rows at 0.9 first, fungi rows at 0.08 last or evicted), and whole-KB inference is infeasible with list-based queues regardless of size. Per-query scoping as `run_drugage_ranking` does today (inject only the requested compounds' rows, pln_runner.py:898-905) remains necessary; the difference is that ALL rows of a requested compound should be injected (revision needs them simultaneously resident: 170 resveratrol rows > BeliefQueueSize 100, and 169 revision steps compete with everything else for MaxSteps), so the queue sizes and step budget must scale with the largest compound's row count, and the hyperon-era 150-row cap (drugage_selector.py:41) becomes a PeTTa budget question instead of a panic avoidance.

## 13. Risks (summary)

1. Semantic mismatch: the KB's strengths are magnitudes and its nodes have no probabilities; lib_pln's deduction needs P(B), P(C) (STV) for every node and returns `(stv 1 0)` whenever `s_BC > P(C)/P(B)` fails the consistency check (:50-54, :89-99).
2. Confidence collapse: `c = s_AB*s_BC*c_AB*c_BC` (:97) cuts confidences 2-11x on existing chains, zeroes anything chained through a zero-strength link (ITP nulls), and has no 0.9 knob; the API threshold semantics and all pinned numbers move.
3. The `Implication A (Not B)` encoding of Neg does not chain (middle term unification :236-237; negation rule :284 is top-level only) — the up/down split is required.
4. Two engines and a new system dependency (SWI-Prolog >= 9.3 + janus) next to hyperon, or an unvalidated move of the whole stack to PeTTa; `git-import!` clones from the network at first run into `./repos` of the CWD unless pinned by SHA (lib_import.pl:82-108).
5. Two lib_pln variants with different formulas and pinned numbers (PeTTa/lib vs trueagi-io/PLN main; the task's "patham9 github" fork is a third source) — the commit must be pinned (4405956 is what this note describes).
6. Control-loop capacity: defaults 10/100/100 keep at most 9 tasks / 99 beliefs (:371), below this KB's closure (128, 256 split) and below the 170 rows of one compound; automatic Inversion/Induction/Abduction by-products (:246-259, :287-292) outrank long deductive chains in the confidence-ranked queues; every PLN.Query recomputes the closure; `println!` floods stdout (:391).
7. Query terms must be ground and `==`-identical (metta.pl:61); one best answer per term (ties by input order); per-path results disappear (procedures that iterate derivations get one revised value).
8. c = 1.0 sentences cannot be revised (`/safe` :10-13 in `Truth_c2w` :71-72) — the `(stv 1.0 1.0)` Lifespan->Mortality bridge (drugage_calibration.metta:226) is safe only in deduction.
9. `explain`'s Chain must be rebuilt from stamps; shared evidence ids or side-route winners break the reconstruction (§10).
10. Determinism depends on tuple order (strict `>` in `BestCandidate` :356, eviction order in `LimitSize`); reproducibility requires a canonical ordering of the generated sentences.
11. Performance is unknown: list-based queues (quadratic `LimitSize`/`ConcatUnique`), full recomputation per query, PeTTa speed unmeasured here because SWI-Prolog is deliberately absent.
12. DrugAge whole-KB reasoning stays out of reach; scoping logic moves from "avoid the hyperon panic" to "fit the PeTTa step/queue budget" and must inject all rows of a compound for revision to mean anything.
